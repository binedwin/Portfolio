PROJECT 02

ROS2 기반 알약 분류 및 자율 배달 로봇 시스템

기간: 2026.05-2026.06
역할: 비전-제어 연동 및 Pick & Place 구현
개발 인원: 2명

개요

  • 알약 분류와 사용자 배송 과정을 자동화하기 위해 YOLO·카메라 기반 3D 위치 인식과 좌표 변환을
    구현하고, ROS2로 로봇팔·컨베이어·AMR을 연동해 인식부터 Pick & Place, 배송까지 이어지는 통합 로봇 시스템입니다.

개발 환경

Simulation Gazebo, RoboDK
Vision/AI YOLO, Roboflow, OpenCV
Interface Vue.js, Chart.js, SQLite, STT/TTS
통신/제어 ROS2 Topic/Action, TCP/IP Socket, TCP/RS232, Modbus, Python threading
로봇/장비 Raspberry Pi, RealSense Camera, conveyor belt, Dobot Magician, TurtleBot

시스템 아키텍처

- 5 -

프로젝트 이미지

담당 역할

  • YOLO + RealSense 기반 3D 객체 위치 인식 파이프라인 구축
  • Transformation Matrix 기반 카메라–로봇 좌표 변환 구현
  • ROS2 Topic/Action 통신을 통한 로봇팔·컨베이어·AMR 모듈 연동
  • Raspberry Pi 제어 및 STT/TTS 음성 인터페이스 적용

트러블슈팅

1. 카메라 좌표와 로봇 좌표 불일치

문제: RealSense/웹캠 객체 위치를 그대로 Dobot Pick 지점으로 쓰면 카메라 좌표계와 로봇 좌표계 차이 때문에 집기 오차가 발생할 수 있었습니다.

해결: Calibration과 Transformation Matrix를 적용해 카메라 좌표를 로봇 좌표로 변환하고 SVD 기반 4x4 Rigid Body Transformation, Scale Ratio 보정 관점으로 오차를 줄이는 흐름을 구성했습니다.

배운 점: 비전 인식 결과는 제어 명령으로 바로 이어질 수 없고 좌표계 정의·보정·반복 검증이 로봇 시스템의 핵심이라는 점을 배웠습니다.

2. Depth 노이즈와 인식 신뢰성

문제: RealSense Depth 값은 물체 표면, 조명, 카메라 위치에 따라 흔들려 3D 위치 산출과 Pick 안정성에 영향을 줄 수 있었습니다.

해결: Depth median filtering과 카메라 기반 Double Check를 적용해 단일 탐지 결과에 의존하지 않고 분류 전후 상태를 다시 확인했습니다.

배운 점: 센서 데이터는 항상 노이즈를 포함하므로 재확인과 필터링을 포함한 검증 흐름이 중요하다는 점을 배웠습니다.

3. ROS2 모듈 간 상태 동기화

문제: 비전 노드, 컨베이어, Dobot, TurtleBot, 대시보드가 독립적으로 동작하면 이동 완료 신호나 Pick 완료 상태가 어긋날 수 있었습니다.

해결: ROS2 Topic, Action, Service 흐름을 기준으로 이미지 구독, 중심점 Publish, Dobot ActionClient 제어, 이동 완료 신호 송수신 구조를 분리했습니다.

배운 점: 분산 로봇 SW는 기능 구현보다 상태 전이와 통신 책임을 명확히 나누는 설계가 중요하다는 점을 배웠습니다.

프로젝트 결과

  • YOLO 객체 탐지, RealSense 3D 위치 인식, Dobot Pick & Place, TurtleBot AMR 배송, Vue 대시보드를 ROS2 기반 End-to-End 흐름으로 통합했습니다.
  • 알약 인식·분류·이송·사용자 전달까지 이어지는 서비스 로봇형 파이프라인을 구현했습니다.
  • 좌표계 변환, 분산 통신, 하드웨어 트러블슈팅, 시스템 통합 경험을 했습니다.

PROJECT 03

수도관 누수 지점 예측 AI 모델

한국통신학회 논문 발표
기간: 2024.07-2024.08
역할: 데이터 검증·모델 비교 및 성능 검증
개발 인원: 4명

개요

  • 센서 데이터의 라벨 누수로 모델 성능이 과대평가되는 문제를 해결하기 위해 라벨 힌트 특성을 제거하고 전처리 방식과 4개 모델을 비교하여, KNN으로 누수 위치 분류 정확도 93.56%와 Macro F1-score 93.14%를 달성했습니다.

개발 환경

데이터 AI HUB 상수관로 누수 감지 데이터셋
특성 FFT Hz amplitude 512 features
모델 Logistic Regression, KNN, Random Forest, MLP
전처리 No normalization, Min-Max, ln(x+1)
성과/근거 KNN Macro accuracy 93.56%, Macro F1-score 93.14%, KICS 논문
- 7 -

프로젝트 이미지

담당 역할

  • 데이터셋 구조 파악 및 데이터 파라미터의 신뢰성 검증
  • 정규화 방식과 머신러닝 알고리즘별 비교 실험 수행
  • 실험 결과를 논문 및 발표 자료로 정리한 문서화 경험

트러블슈팅

1. 과도하게 높은 정확도 의심

문제: Site, Sensor ID, Leak date 같은 특성이 포함되면 모델이 실제 누수 패턴이 아니라 정답 힌트를 학습할 위험이 있었습니다.

해결: 라벨을 쉽게 구분하게 만드는 특성과 생성 방식이 불명확한 특성을 제외하고 FFT 기반 Hz amplitude 512개 특성만 사용했습니다.

배운 점: 정확도 숫자보다 데이터 구성과 라벨 힌트 가능성을 먼저 검증해야 한다는 점을 배웠습니다.

2. 정규화 방식별 성능 해석

문제: 정규화가 항상 성능을 높인다고 단정하기 어려웠고 센서 신호의 거리 구조가 모델별로 다르게 작용할 수 있었습니다.

해결: No normalization, Min-Max, ln(x+1)을 LR/KNN/RF/MLP와 조합해 비교하고 Macro accuracy와 Macro F1-score로 판단했습니다.

배운 점: 전처리는 필수가 아니라 데이터 분포와 모델 특성에 맞게 실험으로 검증해야 한다는 점을 배웠습니다.

3. 불균형 다중 클래스 평가

문제: Normal, Out, In 클래스 수가 달라 단순 accuracy만 보면 특정 클래스 성능 저하를 놓칠 수 있었습니다.

해결: Macro accuracy와 Macro F1-score를 함께 확인해 클래스별 성능을 균형 있게 해석했습니다.

배운 점: 센서 이상 탐지에서는 다수 클래스에 유리한 지표보다 균형 성능을 확인해야 한다는 점을 배웠습니다.

프로젝트 결과

  • AI HUB 상수관로 누수 감지 데이터셋 56,829개 샘플 기반 Normal/Out/In 3-class 분류 실험을 수행했습니다.
  • 정규화 미적용 KNN에서 Macro accuracy 93.56%, Macro F1-score 93.14%를 확인했습니다.
  • 데이터 누수 가능성을 제거한 실험 설계와 결과를 KICS 논문 형태로 정리했습니다.

해결: 팀장으로서 원인을 파악하기 위해 직접 대화를 시도했고, 기술 이해도에 대한 부담과 맡은 역할의 범위가 모호하다는 점을 확인한 후, 역할을 세분화하고 난이도를 조정했으며, 중간 점검 방식을 도입해 참여도를 높였습니다.

배운 점: 팀 문제는 개인의 태도보다 구조와 소통에서 비롯될 수 있음을 깨달았고, 갈등을 방치하기보다 원인을 분석하고 실행 가능한 해결 방안을 설계하는 것이 리더의 역할임을 배웠습니다.

3. AI API 연동 안정성

문제: Vision AI, RAG, STT/TTS, 외부 API가 함께 동작하면 응답 지연이 있다는 사실을 파악했습니다.

배운 점: 여러 AI API 프로젝트에서는 모델 성능보다 전체 사용자 여정과 실패 지점 관리가 중요하다는 점을 배웠습니다.

배운 점: 실서비스는 기능뿐 아니라 공유, 만료, 저장 범위 같은 운영 정책까지 설계해야 한다는 점을 배웠습니다.

배운 점: 실전 Vision 서비스에서는 복잡한 기법보다 환경에 맞는 안정적인 전처리 전략이 중요함을 배웠습니다.

배운 점: 애자일은 문서를 생략하는 방식이 아니라, 가볍고 명확한 요구사항 명세를 반복적으로 갱신해 팀의 구현 기준을 일치시키는 과정임을 배웠습니다.

트러블슈팅

1. 하드웨어 의존성과 분산 통신으로 인한 폭포수 방식의 한계

문제: 문제: 텐던 장력, 모터 가동범위, Vision의 7축 값, ROS 2 토픽과 QoS는 실제 하드웨어를 연결해야 검증할 수 있었습니다. 폭포수 방식에서는 통합 단계마다 기존 설계를 반복해서 수정해야 했고, 이에 따른 재작업으로 전체 개발 일정이 지연됐습니다.

해결: 기능별 구현과 통합 테스트를 반복하는 애자일 방식으로 전환하고, 발견된 문제를 Jira와 요구사항 명세서에 지속 반영했습니다.

결과: 요구사항 명세서를 V7까지 구체화하면서 하드웨어와 소프트웨어의 불일치를 줄이고 프로젝트를 안정적으로 완성했습니다.

2. 손가락 굽힘 판단의 정확도 문제

문제: 손가락 끝점의 거리만으로 굽힘을 판단하면 손의 회전과 카메라 각도에 따라 값이 달라졌습니다.

해결: MCP–PIP–DIP Landmark 벡터의 관절각을 계산하고 손가락별 가동범위로 정규화했습니다.

결과: 손의 위치와 방향이 변해도 편 손과 굽힌 손을 안정적으로 구분할 수 있었습니다.

3. 손 크기·카메라 거리 변화로 인한 엄지축 흔들림

문제: 픽셀 거리만 사용하면 사용자와 촬영 거리에 따라 엄지 대립·벌림 값이 달라지고 축 간 간섭이 발생했습니다.

해결: World Landmark와 관절각, 손바닥 폭 정규화를 적용하고 사용자별 Open/Fist Calibration과 필터링을 추가했습니다.

결과: 개인차와 촬영 환경 변화에도 7축 목표가 급변하지 않는 안정적인 MIMIC 입력을 확보했습니다.

4. 영상 프레임 누적으로 커지는 모방 지연

문제: 처리 속도보다 입력이 빠르면 오래된 프레임이 큐에 쌓여 화면과 로봇 동작이 현재 손 자세보다 늦게 따라왔습니다.

해결: ROS SensorData QoS를 depth=1·BEST_EFFORT로 설정하고, MJPEG도 최신 프레임만 유지하도록 처리했습니다.

결과: 오래된 프레임을 폐기해 실시간 모방과 관제 화면의 지연 누적을 억제했습니다.
